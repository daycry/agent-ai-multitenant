# Changelog

All notable changes to this project are documented in this file.

The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and the project intends to follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

### Why this entry matters

Four things in this batch are worth reading before the lists, because they change
what the rest of the numbers in this repository are worth.

- **Continuous integration gives a verdict again.** CI had been red on `master`
  since 2026-06-26, and a permanently red pipeline is not a signal: nobody can
  tell the new failure from the old one, so pull request #66 was merged red and
  nobody could say whether it was sound. Six separate causes were fixed by reading
  each job's log — among them, CI never created `docker/.env` (so the whole compose
  project aborted before producing a single log), the mypy gate was not running at
  all and looked red because of its wrapper, and `pip-audit --strict` died on the
  first skipped editable install and hid 8 vulnerable packages. Two more jobs were
  neither green nor red: they ran out of clock and GitHub marked them `cancelled`.
  Not one of these was fixed by relaxing anything — no `continue-on-error`, no new
  ignores, no lowered thresholds, no unpinned dependencies.

- **Schema drift went from 162 items to zero.** `alembic check` could not give a
  verdict at all: `migrations/env.py` imported one module of the data layer, so
  `Base.metadata` held 34 of 84 tables, and the missing table reference made the
  command die with a SQLAlchemy traceback that reads like a local problem. With the
  metadata complete the verdict arrived — and it was that an autogenerated
  migration would have proposed dropping `ix_chunks_embedding_hnsw`, the RAG's
  vector index. Anyone adding a column would have got the RAG's silent downgrade to
  sequential search as a free gift.

- **Three real product defects surfaced the moment tests nobody ran were
  uncovered.** All three lived behind jobs that never reported: a delete dialog
  that re-armed enabled after Cancel (so a name-confirmed deletion survived a
  cancel and the next delete was one click, in four screens), a 401 from a
  third-party MCP server that logged the operator out of the panel, and a
  notification-channel form that blanked whatever the operator had typed when the
  transports response landed. None of them was a flaky test.

- **A cache invalidation that had never executed, on any route, now runs.**
  `set_platform_setting` documents two invalidations and the second was drained
  only by the tenant-session factory, which no System Admin route goes through. In
  the ON→OFF direction the córtex could keep its web tools for up to 30 seconds
  after the owner cut the gate: an egress kill-switch with a delay. Fixing it in
  the session rather than in the ten callers surfaced a tenth route nobody had
  looked at — approving or rejecting a plan from the review link was not publishing
  `plan_status_changed`, so the management Kanban froze at exactly that transition.

### Added

- **Governance.** The precedence chain that decides which document wins when two
  contradict (`.docx` > `CLAUDE.md` > written operator decision > later accepted
  ADR > plan > code > intuition), plus a machine-readable `rejects:` field in ADR
  frontmatter so «is this roadmap checkbox rejected by an ADR?» stops being a
  question only prose can answer.
- **Prompt history and an evaluation gate on prompt edits.** `PUT /agents/{id}`
  used to overwrite `system_prompt` with no trace; there is now an append-only
  table with RLS FORCE (migration `0143`) and `GET /agents/{id}/prompt-versions`
  with the diff computed at serve time. Editing a prompt runs the agent's golden
  set, and in the `production` and `customer-external` presets a worse-than-
  threshold result rejects the write with 409, naming which scenarios got worse.
- **The evaluation subject finally sees the prompt.** `LLMSubjectModel.produce`
  sent a single `user` message with no `system`, so two runs of the same dataset
  with different prompts came out statistically identical and «does this edit hurt
  quality?» was unanswerable by construction — with the tables full and the
  dashboard drawing numbers.
- **Marketplace v2, phases 0 and 1**: deployment as a first-class entity
  (migration `0128`), `config_schema` validation, update notifications in the
  catalogue, and a chain test that runs from publishing to the agent actually
  holding the tool and the project actually holding the MCP server.
- **Five partitioned tables**, key-ring rotation and an operable Vault.
- **Session hardening**: httpOnly + Secure + SameSite cookie sessions with
  double-submit CSRF, WebSocket `Origin` validation in the same delivery, and
  invitation-based registration.
- **Córtex phases F2–F5**: affective state, an identity the córtex can propose for
  itself, and the onboarding endpoint wired to a way of using it.
- **Panel internationalisation**: the project hub, the login screen and eleven more
  modules; both registries serve ES and EN.
- **A scripted harness for the 12 end-to-end specs CI does not run** because they
  talk to a real api-server, with the five traps of that setup written down.
- **Dependabot configuration**, and digest pinning extended to a third surface
  nobody had named: the service catalogue, which held the only `:latest` in the
  system, in images that run next to agent code.
- **New guards**, all of them verified failing before being trusted: the shard
  split is reproduced against the real tree so a partition that drops files cannot
  pass green; a marked roadmap checkbox may no longer declare a test file that does
  not exist; the cross-tenant gate may not hang off a shard; and the autogenerate
  comparison now asserts about its own apparatus, not about its result.

### Changed

- **The integration job is split into four shards plus a separate gate job.** The
  suite needs about 72 minutes and the job had a 45-minute clock, so it never
  finished. Branch protection has to require **five** checks now:
  `Integration tests (shard N/4)` for N in 0..3, and the gate.
- **`migrations/env.py` walks the data-layer package** instead of listing imports:
  34 → 84 tables in `Base.metadata`, 53 modules, with an explicit `onerror` because
  `walk_packages` swallows `ImportError` in silence.
- **Models now declare the indexes the migrations created**, in 23 tables. The
  HNSW indexes were verified the only way that counts — dropped in a throwaway
  database and rebuilt from the DDL the model compiles — because Alembic's index
  comparison does not look at `using`, `ops` or `with`.
- **Four files over a thousand lines became packages**, without changing a
  signature.
- **Backup destination adapters are enqueued by the api-server** instead of being
  executed inside it.
- **LangGraph 0.6.11 → 1.2.11** and the LangChain family to 1.x. `websockets`
  deliberately steps back 17.0.1 → 15.0.1 because `langgraph-sdk` 0.4.2 requires
  `<16`; the regression is annotated next to the pin so nobody raises it without
  knowing.
- **One formatter, not two.** With `black` 26.3.1 (forced by two advisories) and
  `ruff` 0.16.3 the two styles stopped agreeing: black reformatted 17 files, ruff
  put them back, and no `git commit` could ever finish. The `black` hook is
  removed.
- **The prettier hook pins a real version.** It pointed at an archived mirror at
  `v4.0.0-alpha.8`, a package that ships no formatter and lets the CLI install
  whatever 3.x is current — measured at 3.8.3 locally against 3.9.6 on the runner,
  with the same `rev` on both sides.
- **markdownlint runs locally too**, with the exact pin CI uses, so a bullet style
  no longer costs a full CI run to discover.
- **The software-composition-analysis gate blocks instead of reporting.** Its
  backlog is empty, and with an empty backlog report-only mode protected nothing:
  it only guaranteed that the next vulnerability would enter `master` behind a
  struck-through green check.

### Fixed

- **The fourteen sandbox images had never been published, and the failure was
  invisible.** `build-runtime-templates.yml` pushed to `ghcr.io/agentic-platform`
  while authenticating with the Actions `GITHUB_TOKEN`, which can only publish to
  the repository owner's namespace, so the destination was unreachable by
  construction. Publication happens only on `master` and branch runs build and scan
  without pushing, so the usual gate stayed green for three weeks; the first run on
  `master` killed all fourteen builds with `denied: permission_denied: The requested
installation does not exist`. The cost was not the red run. `runtime_images.json`
  kept `digests: {}` — its documented fallback — so every host went on building its
  own variant of the fourteen images that carry the container isolation of Guiding
  Principle 2, which is the exact state ADR 0148 was signed to end. The namespace
  now derives from `github.repository_owner`, and a guard refuses any hand-written
  GHCR namespace in a workflow that authenticates with the `GITHUB_TOKEN`; keeping
  the old one would have meant storing a long-lived classic PAT as a repository
  secret, a worse supply chain than the problem it solves. The risk was on record in
  `prod-01` and its mitigation — "decide the registry in the first week" — was never
  carried out.

- **The second cache invalidation of `set_platform_setting` never ran, on any
  route.** Fixed in the session rather than in the callers, which also made the
  review-link verdict publish `plan_status_changed` for the first time.
- **Delete dialogs re-armed enabled after Cancel** in the four screens that use
  name confirmation (projects, teams, agents, knowledge bases).
- **A 401 from an MCP server logged the operator out.** `apiFetch` treats every
  401 as an expired session; the two MCP endpoints answer 401 when the _third
  party's_ credential fails to resolve, which says nothing about the caller.
- **The notification-channel dialog blanked what had been typed** when the
  transports response arrived, leaving Create permanently disabled with no error.
- **The price-sync kill switch could only be thrown with hand-written SQL.**
  `price_sync_enabled` was missing from the platform-settings registry, so its
  endpoint answered 404 while four docstrings promised a System Admin could flip
  it from the panel.
- **Forking an agent onto a taken name returned 500**; it now returns 409 with a
  suggested name.
- **The two tinyproxy healthchecks were never valid** and a `|| true` hid it.
- **The restore preflight stopped services the deployed compose does not
  declare**, and it escalated at step 3 — before restoring anything.
- **The `alembic check` verdict was unobtainable** for every plan that declared it
  as a closing criterion.
- **`uq_task_dependencies_pair` never existed in any database.** PostgreSQL
  silently discards a UNIQUE whose columns are exactly the primary key's inside
  the same `CREATE TABLE` — no error, no notice — so autogenerate proposed it
  forever and the symptom read backwards, inviting exactly the wrong migration.
- **Three migrations created `created_at`/`updated_at` without `nullable=False`**,
  the same slip copied three times against 163 equivalent NOT NULL columns; closed
  by migration `0144` with a backfill first, and reversible.
- **76 roadmap test orders named files that do not exist.** A marked checkbox whose
  command names a missing file asserts a verification that could not have happened.
  The inventory that froze them is now empty.
- **21 roadmap checkboxes stated things that were false**, and three córtex
  checkboxes claimed to be blocked on a human when half of each was executable.
- **A buildx cache served a stale `apt-get upgrade` layer.** `rust-cargo` had
  carried the patch step for weeks and still shipped the old packages: the
  instruction text never changes and the base digest is pinned, so the layer came
  from cache. An image that declares it applies system patches and ships the
  package set of the day the cache was filled is worse than one with no patch step.
- **The evaluation gate died on import**, which reads as «the gate is red».
- **A test that «only passed alone»** was right: it had found a singleton bound to
  the event loop.

### Security

- **A cross-tenant leak, closed.** The backfill table created by migration `0133`
  had no `tenant_id` and no RLS, and `02-roles.sh` leaves an `ALTER DEFAULT
PRIVILEGES` granting `app_user` full DML on every table Alembic creates
  afterwards — verified by measuring `has_table_privilege`, not assumed. Any tenant
  session could read which categories every other customer's projects gate.
  Migration `0138` revokes rather than adding RLS: the application has no reason to
  read that table, and «no access» is stronger than «there is a policy».
- **Five of the six córtex tables had no structural defence** — among them the one
  holding the literal text of the System Owner's conversations. The inference that
  failed: «the córtex is not a tenant resource, therefore no RLS». Migration `0140`
  adds ENABLE + FORCE with a policy on `owner_user_id`.
- **The cross-tenant isolation gate stopped hanging off shard 0.** When that shard
  ran out of clock, `tests/migrations` was left `skipped` and the isolation gate
  did not report — a job that dies halfway does not tell you what it never got to
  do, it omits it.
- **`pip-audit`: 45 vulnerabilities in 12 packages → none**, without a single entry
  in `.pip-audit-ignore`. Six of them were the LangGraph family. `python-jose` was
  the only case that would have justified an exception (its `ecdsa` advisory has no
  fixed version) and it turned out to be venv residue: the code had already
  migrated to `joserfc`, so it was uninstalled instead of excused.
- **CVE-2026-53615** in nine packages of the util-linux family, in the api-server
  image and four runtime templates.
- **Trivy and both `npm audit --audit-level=high` surfaces are at zero** with no
  suppressions: `.trivyignore` and `.pip-audit-ignore` hold no live entries.

### Removed

- `tareas.txt`, and the phase demo scripts from the repository root.
- The `black` pre-commit hook (see **Changed**).
- `getToken` / `setToken` from the panel's auth module — their absence is the
  feature, and a test asserts it so nobody restores them «just for the upload
  endpoint».

## Versioning and releases

This project has never cut a version. Concretely, as measured on 2026-08-21:

| Artefact                              | State                                                                |
| ------------------------------------- | -------------------------------------------------------------------- |
| git tags                              | none                                                                 |
| GitHub releases                       | none                                                                 |
| container registry (ghcr)             | empty — `release-images.yml` has never run                           |
| `agentic-platform-sdk` (PyPI)         | not published                                                        |
| `@agentic-platform/sdk` (npm)         | not published (`private: true`)                                      |
| `version` of every deployable service | `0.0.0` — the two SDK packages say `0.1.0`, and neither is published |

Until a first version is tagged, everything lands under `[Unreleased]`. Cutting
one means, at minimum: deciding the version numbers the components carry (there is
no ADR for that yet), running `release-images.yml` for the first time, and
deciding whether the SDKs are published at all.

## How to add an entry

Two changelogs live in this repository and they answer different questions.

- **This file** is the human-readable history of the repository: what changed, in
  Keep a Changelog sections, newest first. Add to `[Unreleased]` in the same commit
  as the change, and add the same entry to
  [`CHANGELOG.es.md`](CHANGELOG.es.md) — the guard requires both halves to keep the
  same section structure.
- **`docs/07-changelog/{plan_id}.md`** is one entry per roadmap plan, required by
  `CLAUDE.md` before a plan may reach `completed`, and checked by
  `tests/unit/test_roadmap_frontmatter.py`. That format is unchanged; this file
  does not replace it.

The language policy that governs both halves of this file is
[`docs/03-guides/bilingual-docs.md`](docs/03-guides/bilingual-docs.md).
