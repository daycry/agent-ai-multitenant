# Plan 06.6 — tests humanos

Esta guía cubre los **2 tests humanos** del Plan 06.6 (Admin UI gaps
acumulados). Son una recorrida UI de extremo a extremo por las nuevas
piezas del panel: breadcrumbs, comboboxes, markdown textareas,
confirm-by-name dialogs, página de tareas del proyecto, etc.

> **Estado del plan**: `completed` (mergeado a master). La guía queda
> para regresión visual cuando se toque cualquier de las páginas
> afectadas.

## TL;DR

```powershell
.\scripts\dev\up.ps1                              # primera vez
.\.venv\Scripts\python.exe scripts\setup_demo_project.py    # crea project + agente compartidos
.\.venv\Scripts\python.exe scripts\setup_demo_06_6_7.py     # plan + 5 tareas + memorias para 06.7
# luego: abre http://localhost:3000/admin y recorre los checklists de abajo
```

Los dos tests son **manuales** — no hay launcher porque cada uno es
una navegación guiada por el admin-panel. El seed prepara el contexto
visual (proyecto con plan, tareas con badges variados, memorias
similares) para que tengas algo que ver.

## Pre-requisitos

- Stack dev levantado vía `.\scripts\dev\up.ps1` (postgres + redis +
  api-server :8001 + admin-panel :3000).
- Un usuario `tenant_admin` con sesión en el admin-panel. Si arrancas
  desde cero, el primer registro es promovido a `system_admin`
  automáticamente — eso también sirve.
- Seed previo:
  1. `setup_demo_project.py` — proyecto + agente (idempotente al nivel
     de "crea uno nuevo cada vez", deja state en `.demo_state.json`).
  2. `setup_demo_06_6_7.py` — añade un plan con descripción markdown
     - 5 tareas con status variados (incluyendo una en
       `awaiting_human_approval` para que se vea el badge de "tareas
       escaladas") + 4 memorias del demo de 06.7. Lee
       `326cb49f-76d9-40b0-b826-939a1cdb4b9f` como `PROJECT_ID`
       hardcodeado, así que el setup espera ese proyecto del demo
       histórico — adapta el script si tu state es distinto.

> Si nunca has corrido el demo histórico, el `PROJECT_ID` hardcodeado
> en `setup_demo_06_6_7.py` no existe en tu BD. La pista: edita el
> script y reemplaza el UUID por el `project_id` que escribe
> `setup_demo_project.py` en `.demo_state.json`.

## `human_06_6_01` — navegación completa sin teclear URLs

**Qué prueba**: las 6 sub-secciones del hub del proyecto + el sidebar

- los deep-links son accesibles solo con clicks.

**Cómo ejecutarlo**:

1. Login en `http://localhost:3000/login`.
2. Click en sidebar → "Proyectos" → tu proyecto demo.
3. Recorre el hub del proyecto: los 6 cards de sub-sección
   (Plans / Tasks / MCP servers / Knowledge bases / Conversations /
   Configuration) llevan a su sub-página.
4. En cada sub-página, click en cualquier elemento → llega al detail
   sin teclear UUIDs.
5. Edita la descripción del proyecto (markdown), guarda, recarga la
   página: persiste.
6. Intenta borrar el proyecto (botón Trash → dialog) y cancela —
   debe pedirte teclear el nombre exacto antes de habilitar
   "Confirmar".
7. Sidebar → "Memorias" / "Documents" / "Knowledge Bases" / "Settings"
   — todos llegan a una página real.
8. Abre un plan en `pending_human_validation` desde el hub → debe
   haber un link visible a la review session activa.
9. Abre un plan con tareas escaladas → link visible a
   `/admin/plans/{id}/escalated` (badge amarillo).

**Checklist**:

- [ ] Click en card de proyecto en `/admin/projects` → hub del proyecto.
- [ ] Hub muestra las 6 sub-secciones con su link visible.
- [ ] Edit + save del proyecto persiste tras F5.
- [ ] Mismo flujo para agentes (listing → hub → edit → delete).
- [ ] Sidebar: Memorias / Documents / Settings funcionan.
- [ ] Desde plan con tareas escaladas: link visible a `/escalated`.
- [ ] Desde plan en `pending_human_validation`: link visible a la
      review session.

**Pitfalls conocidos**:

- Si abres una sub-sección y el breadcrumb no carga el nombre del
  proyecto, F5: el `ProjectBreadcrumb` fetchea por id y a veces
  el cache de TanStack invalida tarde.
- "Tareas escaladas" sólo aparece si el seed dejó al menos una
  tarea en `awaiting_human_approval` — eso lo hace
  `setup_demo_06_6_7.py`.

## `human_06_6_02` — confirm-by-name dialogs

**Qué prueba**: ningún borrado destructivo procede sin teclear el
nombre exacto del recurso.

**Cómo ejecutarlo**:

1. En cualquier listing (proyectos, agentes, teams, KBs) elige uno
   prescindible (el demo del seed sirve).
2. Click en el icono de borrar → debe abrirse un dialog.
3. El botón "Confirmar borrado" debe estar **deshabilitado**.
4. Teclea cualquier cosa que **no** matchee → sigue deshabilitado.
5. Teclea el nombre exacto (case-sensitive) → se habilita.
6. Click Esc o fuera del dialog → cancela sin borrar.
7. Repite, esta vez confirma → el recurso desaparece del listing
   y al recargar no vuelve.

**Checklist**:

- [ ] Botón "Confirmar borrado" deshabilitado hasta match exacto.
- [ ] Esc / click fuera cancela sin borrar.
- [ ] El borrado respeta cascada del backend (no deja huérfanos —
      al borrar un proyecto sus tareas/planes también se van).

**Pitfalls conocidos**:

- Algunos dialogs ya existían pre-06.6 sin el confirm-by-name (eran
  un sí/no plano). Si encuentras uno así, es candidato a un follow-up
  — el dialog `<Dialog>` del Plan 06.6 acepta prop `size="lg"` por
  defecto pero el confirm-by-name es opt-in.

## Troubleshooting

| Síntoma                                              | Causa probable                                                                          | Fix                                                       |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| El breadcrumb no muestra el nombre del proyecto      | TanStack Query cache no se invalidó                                                     | F5 en la página                                           |
| `setup_demo_06_6_7.py` falla con "project not found" | El `PROJECT_ID` hardcodeado del script no existe                                        | Ajusta el script al `project_id` de tu `.demo_state.json` |
| Modal "Confirmar borrado" no aparece                 | Plan 06.6 sólo lo añadió en proyectos/agentes/teams/KBs                                 | Si es otra entidad, es follow-up                          |
| "Tareas escaladas" no aparece en sidebar de mi plan  | El seed crea una tarea en `awaiting_human_approval` — sin esa, el badge no se renderiza | Re-corre `setup_demo_06_6_7.py`                           |

Errores transversales (Docker, asyncpg, OTel) viven en
`docs/03-guides/gotchas/`.
