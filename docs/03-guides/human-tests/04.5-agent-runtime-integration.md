# Plan 04.5 — tests humanos

Esta guía cubre los **2 demos** del Plan 04.5 (Agent-runtime
integration): `human_04_5_01` (memoria end-to-end) y `human_04_5_02`
(RAG con citas). Cubren los caminos automáticos del Plan 04 que
requieren el agent-runtime hablando con `/internal/agent/*`.

> **Estado del plan**: `completed`. Esta guía queda para regresión de
> los endpoints `/internal/agent/memory-*`, `/internal/agent/rag-*`,
> el Memorizer y la vista de citas en `/admin/documents/{id}/citations`.

## TL;DR

```powershell
.\scripts\dev\up.ps1                                       # stack arriba (1ª vez)
.\.venv\Scripts\python.exe scripts\demos\setup_demo_project.py   # proyecto + agente
.\.venv\Scripts\python.exe scripts\demos\setup_demo_04_5.py      # 2 KBs + 1 Document + grants
.\scripts\dev\run-human-tests.ps1 -Only 04_5               # corre los 2 demos
```

Tiempo: ~10 s sin pausas. Setups idempotentes.

> ⚠️ `API_SERVER_JWT_SECRET`: si arrancaste el api-server **a mano**
> con un secret distinto del default, los demos darán
> `401 Unauthorized`. Usa `up.ps1` (pinea el default) o **no setees**
> esa variable en ninguna terminal — ambos lados leen el default
> pydantic `dev-only-jwt-secret-change-me`.

## `human_04_5_01` — Memory replay end-to-end

**Qué prueba**: ciclo completo de la memoria del agente. Memorizer
destila tras Execution `done` → otra ejecución recupera vía
`memory_recall` → el agente escribe a mano con `memory_store`.

**Cómo ejecutarlo**:

```powershell
.\.venv\Scripts\python.exe .\scripts\demos\demo_human_04_5_01.py
```

Tiempo: ~5 s sin pausas.

**Output esperado** (N = memorias del agente al empezar):

```
========================================================================
  demo human_04_5_01 — Memory replay end-to-end
========================================================================
  Tenant   : tenant-a
  Proyecto : <uuid>
  Agente   : <uuid>
  api-server: http://localhost:8001

──────────────────────────────────────────────────────────────────
  Paso 1/4 — Sembrar una Execution `done`
──────────────────────────────────────────────────────────────────
  [  OK  ]  Execution + Task creadas  — execution_id=<uuid>

──────────────────────────────────────────────────────────────────
  Paso 2/4 — Memorizer destila con LLM fake (2 candidatos)
──────────────────────────────────────────────────────────────────
  [  OK  ]  Memorizer persistio 2 entradas  — reason=ok
  [  OK  ]  memory_entries del agente N → N+2

──────────────────────────────────────────────────────────────────
  Paso 3/4 — `memory_recall` HTTP (lado lectura del agente)
──────────────────────────────────────────────────────────────────
  Token minteado (kind=agent), llamando .../memory-recall
  [  OK  ]  hits devueltos: >=1
    · score=0.0164  bm25=1  vec=None  scope=team_shared
      "El proyecto usa asyncpg como único driver de Postgres."

──────────────────────────────────────────────────────────────────
  Paso 4/4 — `memory_store` HTTP (lado escritura del agente)
──────────────────────────────────────────────────────────────────
  [  OK  ]  memory_store 201  — memory_id=<uuid>
  [  OK  ]  recall encuentra la nueva memoria
```

**Qué demuestra cada `[OK]`**:

| `[OK]`                           | Significado                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Paso 1 Execution+Task            | Conexión SQLAlchemy a Postgres funciona.                                                                      |
| Paso 2 Memorizer 2 entradas      | `should_memorize` autoriza + `distil_execution` parsea + `persist_memory_candidates` guarda con FK al agente. |
| Paso 2 N → N+2                   | Count contra BD coincide (verificación independiente del Memorizer).                                          |
| Paso 3 hits >=1                  | JWT `kind=agent` valida + endpoint resuelve `team_id` del agente + BM25 encuentra.                            |
| Paso 4 memory_store 201          | El agente puede escribir a mano (no sólo destilar).                                                           |
| Paso 4 recall encuentra la nueva | Read-after-write inmediato (no hay sink que drenar).                                                          |

**Checklist**:

- [ ] Los **6 `[OK]`** del demo.
- [ ] `/admin/memories` muestra 3 entradas nuevas (2 destiladas con
      `agent_id` + `source_execution_id`, 1 manual con
      `source: agent_runtime` en metadata). Filtra por
      `scope=team_shared`.
- [ ] `/admin/executions/<execution_id>` muestra **Timeline con 5
      pasos**: `perceive` → `plan` (model_call, 148 tokens, $0.0015)
      → `act` (tool_call `shell_exec`) → `observe` → `finalize`.

> El demo siembra `steps_log` con el **shape canónico** (`index` +
> `node` + `kind` + `status` + `summary`). Si una Execution antigua
> aparece con "Esta ejecución todavía no tiene pasos registrados", es
> shape viejo en BD — no bug actual. TRUNCATE la tabla o re-corre el
> demo para una fila nueva.

**Pitfalls conocidos**:

- `401 Unauthorized` en `memory-recall` → mismatch del JWT secret.
  Ver pre-requisitos.
- `Agent token validation failed: agent not found or revoked` → el
  demo y el api-server no comparten la misma BD. Verifica con
  `docker exec agentic-platform-postgres-1 psql -U migrations_user -d agentic_platform -c "\dt"`.

## `human_04_5_02` — RAG con citas end-to-end

**Qué prueba**: el agente busca en una KB granted a su proyecto y
recibe hits con `chunk_id`/`document_id`/`kb_id` (citas reales) +
puede abrir el documento + puede copiarlo a otra KB.

**Cómo ejecutarlo**:

```powershell
.\.venv\Scripts\python.exe .\scripts\demos\demo_human_04_5_02.py
```

Tiempo: ~5 s.

**Output esperado**:

```
========================================================================
  demo human_04_5_02 — RAG con citas end-to-end
========================================================================
  Paso 1/3 — `rag_search` HTTP x 3 queries
  Query: «tenant_id RLS»
    1. rrf=0.0164  bm25=1  vec=None  rerank=1.000
       "Multi-tenancy desde el día uno: ..."
       cita → kb_id=<uuid>  document_id=<uuid>  ordinal=0
  Query: «sandbox agent-runtime»  → 1 hit
  Query: «asyncpg»                → 1 hit
  [  OK  ]  Al menos una query devolvió hits

  Paso 2/3 — `document_convert` (vista «open document»)
  [  OK  ]  Document devuelto: «Notas de arquitectura»  — 4 chunks
    ord=0  "Multi-tenancy desde el día uno: ..."
    ord=1  "Los workers nunca ejecutan código del usuario: ..."
    ord=2  "El acceso a BD desde dev usa asyncpg + SQLAlchemy ..."
    ord=3  "El sandbox habla con el api-server por /internal/agent/* ..."

  Paso 3/3 — `promote_to_kb` (copiar doc a una KB destino)
  [  OK  ]  promote_to_kb 201  — new doc <uuid> · chunks=4
```

**Checklist**:

- [ ] Los **3 `[OK]`** del demo.
- [ ] `/admin/projects/<project_id>/knowledge-bases` muestra dos KBs
      granteadas: "Arquitectura del sistema (demo 04.5)" y "KB destino
      del demo (04.5)".
- [ ] `/admin/documents/<doc_id>/citations` (original o promovido)
      muestra: título "Notas de arquitectura", badge `application/pdf`,
      **2 páginas A4 placeholder** y **4 rectángulos azules** en
      las posiciones esperadas (pág 1: chunks 0+1; pág 2: chunks 2+3).
- [ ] Panel lateral derecho muestra el texto completo de cada chunk.
      Hover sobre rectángulo azul = tooltip; click en chunk del panel
      = scroll automático + resaltado verde.
- [ ] `/admin/documents/<doc_id>/ingestion` muestra badge verde
      **Indexado** y card de Eventos con
      _"Documento ya indexado. No hay pipeline corriendo, …"_.

> El demo siembra el Document como `application/pdf` con bboxes
> simulados para que `/citations` funcione completo. El renderizado
> del PDF real con PDF.js es follow-up; la página fija la **superficie**
> citación → página → bbox; el contenido visual viene después.

> La ruta `/admin/documents/<id>` (sin sufijo) devuelve **404** — sólo
> existen `/citations` e `/ingestion`. Si te llega un link sin sufijo,
> añade `/citations`.

**Pitfalls conocidos**:

- "Pendiente" en `/ingestion` cuando el doc está `indexed` → cache
  viejo del admin-panel. Ctrl+F5 o `down.ps1 && up.ps1`.
- `cz-shortcut-listen` en la consola del navegador → ColorZilla
  (extensión). El admin-panel ya tiene `suppressHydrationWarning`;
  Ctrl+F5 para forzar recarga del bundle nuevo.
