## TL;DR

No hay `setup_demo_09_1.py` ni launcher dedicado. El setup es manual: lo
clave es **correr los seeds** para que el catálogo oficial exista
(`seed_marketplace_listings` ya está cableado en `seeds/__main__.py`):

```powershell
.\scripts\dev\up.ps1                          # api-server :8001 + admin-panel :3000 + postgres + redis
.\.venv\Scripts\python.exe -m api_server.seeds # siembra built-ins + listings oficiales (idempotente)
```

Luego abre el marketplace en el admin-panel:

```
http://localhost:3000/admin/marketplace          # catálogo (con listings oficiales) + CTA "Publicar"
http://localhost:3000/admin/marketplace/private   # publicar skill/tool privada (pegar manifest)
```

Para los formatos de manifest (SKILL.md, tool.yaml, mcp_server) y qué
deriva el servidor, ver la guía
[`docs/03-guides/publicar-en-marketplace.md`](../publicar-en-marketplace.md).

## `human_09_1_01` — El marketplace ya no está vacío y publicar es obvio

**Qué prueba**: tras sembrar, el catálogo muestra los listings oficiales
con badge VERIFIED; hay un CTA claro a publicar; un `tenant_admin` puede
publicar un listing privado pegando un manifest de ejemplo; un manifest
malformado da 422 sin crear fila; despublicar retira el propio listing
pero los oficiales son intocables desde el tenant; y otro tenant no ve el
listing privado.

**Precondiciones**:

- Seeds aplicados (`python -m api_server.seeds`) — el catálogo oficial
  existe.
- Login como `tenant_admin`.
- (Para el último step) un segundo tenant disponible.

**Pasos**:

1. Abre `http://localhost:3000/admin/marketplace`: en el catálogo deben
   verse los **listings oficiales** (al menos **Playwright** + varias
   **skills**) cada uno con su badge **VERIFIED** (global).
2. Localiza el **CTA "Publicar"** en la pantalla principal del
   marketplace: debe llevar a `/admin/marketplace/private`.
3. En la pantalla de publicación, usa la **plantilla/ejemplo SKILL.md**
   insertable y publícala como `tenant_admin` → se crea un **listing
   privado del tenant** (community, aislado por RLS), visible en tu
   propio catálogo.
4. Pega ahora un manifest **mal formado** (rompe el frontmatter o un
   campo requerido) y publica → debe devolver **422 con un mensaje claro**
   de qué falla y **no** crear ninguna fila.
5. **Despublica** el listing privado que acabas de crear → desaparece de
   tu catálogo. Comprueba que los listings **oficiales no se pueden
   tocar** (no hay botón despublicar/editar sobre ellos desde el tenant).
6. (Aislamiento) Loguéate en **otro tenant** y abre `/admin/marketplace`:
   **no** debe aparecer el listing privado que publicaste en el primer
   tenant.

**Resultado esperado**: catálogo con oficiales VERIFIED; CTA a publicar
visible; publicación de un privado OK; manifest malo → 422 sin fila;
despublicar retira el propio, los oficiales intocables; aislamiento
cross-tenant respetado.

**Checklist**:

- [ ] Ir a `/admin/marketplace` → se ven listings oficiales (Playwright +
      skills) con su badge VERIFIED.
- [ ] Hay un CTA claro para "Publicar" que lleva a
      `/admin/marketplace/private`.
- [ ] Como `tenant_admin`, pegar el manifest de ejemplo SKILL.md → se
      publica un listing privado del tenant.
- [ ] Un manifest mal formado → 422 con mensaje claro, no se crea fila.
- [ ] Despublicar un listing propio lo retira; los oficiales no se pueden
      tocar desde el tenant.
- [ ] Otro tenant NO ve el listing privado (aislamiento).

**Pitfalls conocidos**:

- Si el catálogo sigue **vacío** tras `up.ps1`, faltó correr los seeds:
  `seed_marketplace_listings` solo se aplica al ejecutar
  `python -m api_server.seeds` (idempotente, re-ejecutar no duplica).
- Los **oficiales** son VERIFIED + `official-catalog` + **globales**
  (`tenant_id NULL`): se siembran a nivel plataforma y ningún tenant
  puede editarlos/despublicarlos. Los **privados** son COMMUNITY +
  `tenant_id` del caller, aislados por RLS.
- El `tenant_id`, la fuente privada y el `trust_level` los **deriva
  siempre el servidor**, nunca el wire: no se puede falsificar un privado
  como global/verified (RLS WITH CHECK lo rechaza).
- Publicar requiere rol `tenant_admin`: un `tenant_user` recibe 403.

## Troubleshooting

| Síntoma                               | Causa probable                                          | Fix                                                                       |
| ------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------- |
| El catálogo sigue vacío tras `up.ps1` | Los seeds no se aplicaron                               | `.\.venv\Scripts\python.exe -m api_server.seeds` (idempotente)            |
| Re-correr el seed duplica listings    | (No debería) el upsert es por identidad de listing      | Verifica `source=official-catalog` + nombre + versión; reporta si duplica |
| Publicar da 403                       | El usuario no es `tenant_admin`                         | Loguéate con un usuario `tenant_admin` del tenant                         |
| Manifest válido pero publica 422      | Frontmatter/campos del SKILL.md o tool.yaml incorrectos | Usa la plantilla insertable de la pantalla; revisa el mensaje del 422     |
| Otro tenant ve el listing privado     | (No debería) RLS no aplicada                            | Verifica que la sesión corre bajo `app.tenant_id`; reporta si se filtra   |

Errores transversales viven en `docs/03-guides/gotchas/`.
