## Resumen

Hoy los proveedores LLM (ADR 0021: Claude Agent SDK, GitHub Copilot, Azure AI Foundry vía APIM, Ollama)
**solo se configuran en el instalador** (Fase 15, paso 5) y sus credenciales viven en Vault
(`secret/platform/llm-providers`). No existe ninguna pantalla en el panel para verlos, crearlos, editarlos,
rotar credenciales o probar la conexión post-instalación — exactamente el hueco que el operador encontró. El
ADR 0028 ya fijó el diseño: los proveedores son **platform-global, gestionados solo por `system_admin`**, con
sus secretos en Vault. Este plan **materializa la tabla `llm_providers` + el backend CRUD + la página
`/admin/llm-providers`** (más el Device Flow de Copilot y el cableado del factory de runtime), reutilizando lo
que ya existe (catálogo de precios `model_prices` / `/admin/model-prices`, cliente Vault, RBAC `system_admin`).

## Alcance

**Entra**:

- Tabla `llm_providers` platform-global (sin `tenant_id`, sin RLS; acceso solo vía engine BYPASSRLS de los
  endpoints `system_admin`), por ADR 0028 §Esquema.
- Backend `system_admin`: `GET/POST /admin/llm-providers`, `GET/PUT/DELETE /admin/llm-providers/{id}`,
  `POST /admin/llm-providers/{id}/test` (probar conexión). **Credenciales solo a Vault** (`SecretStr`, nunca
  en texto plano en BD/logs/respuestas; `secret_vault_path` por proveedor: `platform/llm/<provider_id>`).
- Device Flow de GitHub Copilot: `POST /admin/llm/copilot/device-flow/start` + `…/poll` que acuña el token y lo
  guarda en Vault (ADR 0021 §"Device Flow en la admin-panel"; tarea diferida task_03_32).
- Cableado: el factory de selección de proveedor del runtime (`shared-llm` / `agent-runtime`) lee la config de
  `llm_providers` + el secreto de Vault (con **fallback** a las variables de entorno/installer actuales, sin
  romper lo existente).
- UI admin-panel: página `/admin/llm-providers` (RoleGuard `system_admin`, shadcn/ui moderno) con lista +
  formulario por tipo de proveedor (campos de credenciales correctos por `kind`) + toggle activo + botón
  "probar conexión" + UI del Device Flow de Copilot. Entrada en el menú lateral.
- Reconciliación ligera con el catálogo de modelos existente (`model_prices`): asociar cada modelo a su
  `provider` (sin reconstruir el catálogo de precios ni el sync de LiteLLM ya existentes).
- Tests automáticos por tarea + docs (ADR 0028 → "implementado", matriz RBAC, guía, changelog).

**Queda fuera**:

- Reescribir el catálogo de precios `model_prices` o el sync desde LiteLLM (ya existe — solo se asocia provider).
- Migrar JWT a httpOnly cookies (Plan 15).
- `tenant_model_allowlist` / `tenant_pricing_override` (escape hatches futuros, ADR 0028).
- BYOK per-tenant de credenciales (ADR 0028 lo rechaza como default).

## Decisiones clave

- **Scope plataforma, no tenant**: todo es `system_admin`. El `tenant_admin` sigue eligiendo
  `agents.llm_provider` + `agents.llm_model` (Plan 06.8) pero no toca proveedores. NO se mezcla con la
  asignación de tools por agente (scope tenant) — eso es el Plan siguiente.
- **Secretos solo en Vault**: el endpoint recibe la credencial (`SecretStr`), la escribe en Vault y persiste
  únicamente `secret_vault_path` en BD. Nunca se devuelve la credencial en una respuesta (write-only). Patrón
  igual al de los MCP servers per-proyecto (ADR 0025) y al bootstrap del instalador (`vault_bootstrap.py`).
- **No romper el arranque actual**: el factory de runtime mantiene el fallback a env/installer; si hay fila en
  `llm_providers`, esa gana; si no, se usa lo de hoy. Migración aditiva.
- **Catálogo de modelos = reutilizar**: `model_prices` ya es el `llm_model_catalog` del ADR 0028 (materializado
  en Plan 11). Aquí solo se añade la asociación modelo→proveedor; no se duplica.

## Tareas

### Fase A — Modelo de datos + backend de proveedores

#### `task_11_2_01` — Tabla `llm_providers` + ORM + migración

- [x] **Título**: Tabla `llm_providers` (id, kind ∈ {claude_sdk, copilot, azure_foundry, ollama}, display_name,
      base_url nullable, secret_vault_path nullable, is_active default true, config JSONB para no-secretos,
      created_at, updated_at). Platform-global (sin tenant_id, sin RLS). Migración Alembic reversible (0070+,
      cabeza única). Modelo ORM + repositorio.
- **Tests**: `pytest tests/migrations/test_llm_providers_table.py -v` (crea/borra reversible; sin RLS; CHECK del kind)

#### `task_11_2_02` — Backend CRUD `system_admin` + Vault + test-connection

- [x] **Título**: Router `/admin/llm-providers` (GET list/POST/GET{id}/PUT{id}/DELETE{id} + POST {id}/test), todo
      `system_admin`. Validación por `kind` (campos requeridos). La credencial llega como `SecretStr`, se escribe en
      Vault en `platform/llm/<provider_id>` y se guarda solo `secret_vault_path`; **nunca** se devuelve. `/test`
      hace una llamada mínima al proveedor (con el secreto leído de Vault) y devuelve ok/err clasificado.
- **Tests**: `pytest tests/integration/test_llm_providers_admin.py -v` (CRUD persiste; secreto va a Vault y no se
  echo-ea; no-`system_admin` → 403; `/test` ok/err)

### Fase B — Device Flow Copilot + cableado runtime

- **Tests**: `pytest tests/integration/test_provider_factory_db_config.py -v` (fila activa gana; sin fila → fallback)
