## Resumen ejecutivo

Auditoría posterior al Plan 06 reveló que el **backend** del admin
expone CRUD completo para `Project`, `Agent`, `Team` (PUT + DELETE),
pero la **UI** solo emite **listing + create**. Las cards del listing
no son clickables, las páginas de detalle no existen, y las sub-páginas
introducidas en Plans 05/06 (mcp-servers, agent-tools-diagnostic,
dep-cache, review, escalated-tasks) son **huérfanas**: solo se llega a
ellas con la URL en mano.

Este plan cierra la deuda — sin tocar backend, solo añadiendo las
pantallas que faltaban y enlazando todo a través de un layout
coherente.

## Contexto — qué auditó

```bash
# Listings vs detalles

# Acciones de PUT/DELETE en el backend
```

## Alcance

**Entra**:

- **Vista hub del proyecto** `/admin/projects/[id]/page.tsx` que:
  - Muestra los campos editables (`name`, `description`, `status`,
    `team_id`).
  - Permite editar (dialog con form + PUT a `/projects/{id}`).
  - Permite borrar (con confirm dialog + DELETE).
  - Lista las 6 sub-secciones del proyecto con su icono + link.
- **Listing de proyectos clickable**: cada card lleva al hub.
- **Vista de detalle/edit de agente**
  `/admin/agents/[id]/page.tsx` (mismo patrón que Project).
- **Crear agente** desde `/admin/agents/page.tsx`: botón "Nuevo
  agente" + dialog con form.
- **Sidebar dentro del proyecto** (sub-nav): un layout
  `app/admin/projects/[id]/layout.tsx` que renderiza tabs / nav
  lateral con las 6 sub-páginas siempre visibles.
- **Sidebar global completo**: añadir Memorias, Documentos y
  Settings a `admin-shell.tsx`.
- **Link al panel de tareas escaladas** desde la página del plan
  (`/admin/projects/[id]/plans/[planId]/page.tsx`).
- **Link a una review session** desde el plan en
  `pending_human_validation`.
- **Borrado de team** desde `/admin/teams/[team_id]/page.tsx`.
- **Tests Playwright** que pinean los nuevos flujos: navegación
  desde listing → detalle → edit → save → list reflejado.

**Queda fuera**:

- Cambios en el backend (los CRUD ya existen).
- Refactor del sistema de componentes shadcn — se usa lo ya disponible.
- Internacionalización (sigue ES + EN como hoy).
- Bulk operations (multi-select para borrado masivo, etc.).

## Decisiones clave

- **Hub de proyecto antes que tabs**: el detail page renderiza UNA
  vista (campos del proyecto) + lista visual de las 6 sub-secciones.
  No usamos un router-level layout con tabs porque las sub-páginas
  ya son standalone y el operador navega a ellas con un click. Si más
  adelante se necesita layout compartido (breadcrumbs, header per
  proyecto), se evolucionará desde aquí.
- **Edit en dialog, no en página separada**: para `Project` y
  `Agent` el set de campos cabe en un dialog modal — añade menos
  navegación, evita una ruta más.
- **Cards del listing como `<Link>`**: el patrón Next.js para
  navegación es preferible a `onClick` con `router.push`; es lo que
  ya hace `teams/page.tsx` para el detalle de team.
- **Borrado siempre con confirm dialog**: nunca un botón rojo
  directo. El confirm pide volver a teclear el nombre del recurso
  (patrón GitHub) para resources con dependencias (Project,
  Team).
