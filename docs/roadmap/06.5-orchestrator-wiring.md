## Resumen

Plan 06 entregó los **módulos individuales** (worker-test, dep-cache,
worktrees + bare repos, pool elástico, plan-git workflow, review-runtime,
task lifecycle, plan progress) con sus tests verdes y un
`plan_runner.py` síncrono que los integra para tests humanos.

Plan 06.5 cablea esos módulos en la **infraestructura productiva**:
Celery + DB + endpoints + beat scheduler + integración con el agente
reviewer LangGraph.

## Alcance

**Entra**:

- **Celery tasks** que invocan los módulos asincrónicamente:
  - `run_test_runtime(task_id)` — invoca `workers.test_runtime.TestRuntimeRunner.launch`.
  - `compose_review_runtime(plan_id)` — invoca `ReviewRuntimeManager.create`.
  - `idle_sweep_pools` (beat, cada 30s) — invoca `RuntimePool.sweep_idle` sobre todos los pools activos.
  - `purge_dep_cache` (beat, diario) — invoca `DepCacheManager.purge_expired`.
  - `prune_worktrees` (beat, diario) — invoca `WorktreeManager.prune_idle`.
  - `expire_review_runtimes` (beat, cada 5 min) — invoca `ReviewRuntimeManager.expire_overdue` + `suspend_idle`.

- **DB migrations** Alembic:
  - `review_sessions` table — persiste sesiones para que el manager sobreviva un reinicio de worker.
  - `task_audit_events` table — append-only, source of truth del audit log.

- **Endpoints REST** nuevos en api-server:
  - `GET /api/v1/tasks/{task_id}/history` — devuelve `lc.history(task_id)` serializado.
  - `POST /api/tasks/{task_id}/human-action` — invoca `lc.apply_human_action`.
  - `POST /api/plans/{plan_id}/free-task` — invoca `lc.create_free_task`.
  - `POST /api/plans/{plan_id}/escalated-tasks` (GET list) — `lc.list_escalated`.
  - `POST /api/review/{session_id}/rerun` — `mgr.queue_rerun`.
  - `WS /ws/review/{session_id}/logs` — proxea stdout del container del review-runtime.
  - `GET /review/{session_id}` — verifica `sig`/`exp` y sirve el SPA del review.

- **Integración con el agente reviewer**:
  - Después de `worker_test`, llamar al agente con `reviewer_input_block(reports)` inyectado en el system prompt.
  - Si el agente devuelve `verdict='reject'`, invocar `lc.reject_review` con la `ReviewComment` extraída.

- **Spin-up real de containers** en `workers.test_runtime` y `workers.review_runtime`:
  - Crear bridge docker por task.
  - Lanzar postgres-test / redis-test reales.
  - Lanzar el main image del review-runtime con compose efímero.

**Queda fuera**:

- Construcción de UI nueva — la UI ya está en Plan 06 (dep-cache page, review page, escalated page). El plan 06.5 solo le cablea los endpoints reales que mock-eaban los Playwright specs.

## Riesgos

| Riesgo                                               | Probabilidad | Impacto | Mitigación                                                                            |
| ---------------------------------------------------- | ------------ | ------- | ------------------------------------------------------------------------------------- |
| Regresión en Plan 02 al tocar `apps/orchestrator/`   | Media        | Alto    | Tests integration existentes deben seguir verdes. CI bloquea el merge.                |
| Migrations rompen datos seedeados en dev             | Media        | Medio   | Migrations reversibles + smoke en `docker-compose.dev` antes de mergear.              |
| Endpoint REST expone secretos (review-runtime token) | Baja         | Crítico | Test pin de scope per-tenant + auditoría manual al ADR de seguridad antes de mergear. |

- [x] **Título**: Spawn real del review-runtime container vía

- **Estado**: `workers.compose_review_runtime` persiste primero la
  fila `review_sessions` (recuperable) y luego intenta el spawn vía
  `docker.from_env()` con la misma envolvente endurecida que
  `agent-runtime` (cap-drop ALL, no-new-privileges, read-only root,

  cambio de contrato del task.
