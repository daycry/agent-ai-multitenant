## Descripción Detallada

### Resumen Ejecutivo

Cerrar la deuda de integración del Plan 04: cablear el Memorizer al
trigger automático tras cada `Execution`, sustituir los cinco
placeholders 501 del agent-runtime por adapters que llaman al backend
nuevo, y dar al chat un componente de file upload para que
`document_convert` y `promote_to_kb` sean invocables desde la
conversación. Es un plan **de integración**, no de producto nuevo —
todo el backend ya existe y está testeado.

### Contexto

Plan 04 entregó las funciones Python + endpoints REST + UI admin de
toda la pila de memoria y RAG. 200+ tests verde. Pero tres piezas de
cableado no entraron en el scope de sus 26 tareas:

1. **El Memorizer existe** como módulo (`api_server.memorizer.*`)
   pero no hay Celery task que lo dispare al cerrar una `Execution`.
   Las memorias sólo entran al store por `POST /memories` manual.
2. **Los cinco tools** del agent-runtime que Plan 02 dejó como
   placeholder 501 (`memory_recall`, `memory_store`, `rag_search`,
   `document_convert`, `promote_to_kb`) siguen devolviendo 501.
3. **El chat no acepta archivos**: el flow conversacional del
   `human_04_03` ("pega un PDF en el chat") es imposible.

Sin estas tres piezas, los humanos `human_04_01`, `_02` y `_03` del
Plan 04 no son ejecutables end-to-end. El changelog de Plan 04 los
marcó como deferred a este plan.

### Alcance

**Entra en este plan**:

- Celery task `workers.memorize_execution` que recibe
  `execution_id`, abre sesión, valida la policy con
  `should_memorize`, llama a `distil_execution` con un
  `LLMProvider` real (provider del agente o default Ollama) y
  persiste con `persist_memory_candidates`.
- Trigger desde `workers/execution.py` que enqueueña la task al
  finalizar una ejecución con `status='done'`.
- Adapters en `agent-runtime` que sustituyen los cinco placeholders 501. Cada adapter llama al backend correspondiente vía un endpoint
  REST interno (no SQL directo desde el sandbox).
- Componente de upload/paste de fichero en el chat (paste-en-text
  para PDFs, drag-and-drop). Hook que dispara `document_convert` y
  ofrece un botón "promover a la KB".
- Tests: 5 unit/integration por tool + 1 integration por chat
  upload + 1 integration del trigger del Memorizer.

**Queda fuera**:

- Endpoints REST nuevos para los tools (los que hay valen).
- Re-embedding masivo (`human_04_05` sigue deferred a Plan 12).
- Cualquier feature nueva de memoria o RAG — Plan 04 ya cubrió
  el alcance.

### Decisiones Clave

- **Endpoint REST como vehículo de los tools**, no SQL directo. El
  sandbox del agent-runtime no debería tener credenciales de BD;
  con esto mantenemos el principio de mínimo privilegio de ADR 0012.
- **`document_convert` no persiste**. Ya estaba decidido en Plan
  04 task_04_22; lo recuerdo aquí porque el chat necesitará dos
  pasos visibles: "convertir" (instantáneo, in-flight) y "guardar
  a la KB" (acción separada).
- **El Memorizer usa el `LLMProvider` del agente que ejecutó la
  tarea**, no un provider fijo. Si el agente corrió con Claude, se
  destila con Claude; si corrió con Ollama, con Ollama. Esto evita
  surprises de coste y deja la elección al diseñador del agente.

### Riesgos Identificados

| Riesgo                                                              | Probabilidad | Impacto | Mitigación                                                                                    |
| ------------------------------------------------------------------- | ------------ | ------- | --------------------------------------------------------------------------------------------- |
| El cableado expone un caso de RLS no cubierto por los tests Plan 04 | Baja         | Alto    | Tests de integración por tool + smoke test cross-tenant antes del cierre.                     |
| El Memorizer falla y bloquea el cierre de ejecuciones               | Media        | Medio   | Trigger asíncrono via Celery, fire-and-forget. Errores se logean pero no rompen la Execution. |
| El paste de PDFs en el chat es accesible-hostil en Safari/Firefox   | Media        | Bajo    | Drag-and-drop como fallback siempre disponible; el paste es opcional.                         |
