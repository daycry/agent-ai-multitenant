## Descripción Detallada

### Resumen Ejecutivo

Cerrar la deuda de integración del Plan 04: cablear el Memorizer al
trigger automático tras cada `Execution` y sustituir los placeholders
501 del agent-runtime por adapters que llaman al backend RAG/memoria
a través de **un nuevo endpoint family `/internal/agent/*`** con auth
dedicada (token de sandbox, no JWT humano). Plan de integración, no
de producto nuevo.

### Contexto

Plan 04 entregó las funciones Python + endpoints REST + UI admin de
toda la pila de memoria y RAG. 200+ tests verde. Tres piezas de
cableado quedaron fuera del scope:

1. **El Memorizer existe** como módulo (`api_server.memorizer.*`)
   pero no hay Celery task que lo dispare al cerrar una `Execution`.
2. **Los placeholders 501 del agent-runtime** (`memory_recall`,
   `memory_store`, `document_convert`) siguen devolviendo 501. Plus:
   `rag_search` y `promote_to_kb` ni existen como tools en el
   registry (Plan 02 sólo dejó los tres primeros como placeholders;
   los otros dos son conceptos nuevos de Plan 04).
3. **El agent-runtime no tiene canal HTTP de vuelta al api-server**.
   El patrón existente (`OrchestrationSink`) sólo cubre writes
   fire-and-forget como `kanban_update`; no soporta tools que
   devuelvan datos durante el run (como `memory_recall` o
   `rag_search`).

Resultado: hay que crear infraestructura nueva, no sólo "cablear
placeholders". Detalle de la decisión en el ADR pendiente que
acompaña este plan.

### Alcance

**Entra en este plan**:

- **Nueva auth `/internal/agent/*`**: middleware FastAPI que
  valida un token específico de sandbox (no JWT humano), bind del
  `agent_id` al request, propagación del `tenant_id` para que la
  sesión RLS funcione.
- **Worker mintea el token al lanzar el contenedor**, lo inyecta
  como variable de entorno (`AGENTIC_INTERNAL_TOKEN`), y la
  imagen `agent-runtime` lo lee al construir su cliente httpx.
- **Cinco endpoints** bajo `/internal/agent/`:
  `memory-recall`, `memory-store`, `rag-search`,
  `document-convert`, `promote-to-kb`. Cada uno reusa la función
  backend que Plan 04 dejó lista.
- **Cliente httpx + cinco tool adapters** dentro de `agent-runtime`
  que sustituyen los placeholders 501 y registran las dos tools
  nuevas (`rag_search`, `promote_to_kb`).
- **Celery task `workers.memorize_execution`** que recibe
  `execution_id`, valida la policy, llama a `distil_execution`
  con el provider del agente, y persiste con
  `persist_memory_candidates`.
- **Trigger desde `workers/execution.py`** que enqueueña la task
  al finalizar una ejecución con `status='done'`. Best-effort —
  un fallo del Memorizer no rompe la Execution.
- **ADR nuevo** documentando la decisión "HTTP `/internal/agent/*`
  - token de sandbox" frente a las alternativas (sink-only,
    pre-inyectar contexto).

**Queda fuera**:

- Chat con file upload (`human_04_5_03` original). Movido al
  arranque de Plan 07. `document_convert` queda usable
  programáticamente desde el agent loop pero no desde el chat.
- Re-embedding masivo (`human_04_05` sigue deferido a Plan 12).
- Endpoints REST públicos nuevos — los que hay para los humanos
  siguen valiendo.

### Decisiones Clave

- **`/internal/agent/*` con token de sandbox**, no JWT humano. El
  worker mintea un token corto (24h TTL) al lanzar el container
  cuyo subject es el `agent_id`. El middleware valida + carga
  `tenant_id` del agente para que RLS funcione. Mismo principio
  de mínimo privilegio que ADR 0012 — el sandbox sólo puede
  hablar con `/internal/agent/*`, no con el resto del API.
- **Reads van síncronos por HTTP**, no por sink. Memory recall y
  RAG search devuelven datos que el agente USA inmediatamente; el
  patrón sink es post-hoc y no encaja.
- **Writes (`memory_store`, `promote_to_kb`) también por HTTP**
  por consistencia. Implica que `read-after-write` dentro del
  mismo run funciona (escribes una memoria, dos pasos después la
  recall'as y la ves). Alternativas (sink-only, híbrido)
  rechazadas — ver ADR 0024.
- **El Memorizer usa el `LLMProvider` del agente que ejecutó la
  tarea**, no un provider fijo. Sin sorpresas de coste.

### Riesgos Identificados

| Riesgo                                                                  | Probabilidad | Impacto | Mitigación                                                                                                           |
| ----------------------------------------------------------------------- | ------------ | ------- | -------------------------------------------------------------------------------------------------------------------- |
| Token de sandbox filtra y un atacante hace cross-tenant via /internal   | Baja         | Alto    | TTL 24h + `agent_id` bind en el token + RLS por debajo. Tests cross-tenant en el suite de integración.               |
| Tools síncronos añaden latencia al agent loop (HTTP roundtrip por call) | Media        | Bajo    | El sandbox y el api-server viven en la misma docker-net; latencia ~ms. Logs estructurados para medir.                |
| Memorizer falla y bloquea el cierre de ejecuciones                      | Baja         | Medio   | Trigger fire-and-forget; errores se logean. Si el embedder está caído, la fila queda con `embedding=NULL` (BM25 ok). |
