## Resumen

Los Planes 06.11/06.12 dejaron el subsistema KB **funcional y
consistente**: la ingesta corre, el RAG está saneado, y las KB built-in
son visibles/grantables (patrón A, ADR 0029). Pero quedaron dos piezas
de seguimiento, anotadas como "queda fuera" en esos planes:

1. **Las KB built-in están vacías** — son contenedores sin chunks. Hacen
   de catálogo navegable, pero conceder una a un proyecto no aporta
   contenido al RAG hasta que tengan documentos indexados.
2. **`apply_template_kb_grants` es código muerto** — el helper que
   pre-concede las KBs de stack al crear un proyecto desde plantilla
   existe ([`seeds/template_adoption.py`](../../apps/api-server/src/api_server/seeds/template_adoption.py))
   pero **ningún router lo llama**. Crear un proyecto desde plantilla no
   pre-grantea nada. Estaba bloqueado por la invisibilidad de built-ins
   (resuelta en 06.12).

Este plan cierra ambas.

## Alcance

**Entra**:

### Fase A — Poblar el catálogo built-in

- **Fuentes canónicas**: definir el corpus de cada una de las 6 KB
  built-in (python-fastapi, node-express, php-symfony, postgresql,
  react-nextjs, api-rest-guidelines) como ficheros `.md` versionados en
  el repo (p.ej. `packages/shared-kb-catalog/` o
  `apps/api-server/.../seeds/catalog/`). Contenido conciso y curado, no
  un dump masivo.
- **Ingesta de catálogo**: un proceso (script/seed) que, bajo el
  platform tenant, parsea esos `.md` con el pipeline existente
  (`ingest_document` / chunking + embeddings) y persiste documents +
  chunks `tenant_id = PLATFORM_TENANT_ID`. Idempotente (chunk ids
  estables por hash del contenido). Reutiliza la infra de 06.11.
- **Decisión a tomar (ADR si hace falta)**: ¿ingesta en build-time del
  seed, o un cron de refresco? ¿Docling sobre los `.md` o un chunker
  markdown ligero sin docling-serve?

### Fase B — Auto-grant por plantilla

- **Cablear `apply_template_kb_grants`** en la creación de proyecto
  (POST de proyecto desde plantilla / wizard): tras crear el proyecto,
  resolver los `default_kb_grants` de la plantilla y crear las filas
  `kb_projects`. Ya destrabado por 06.12 (built-ins resolubles).
- Test de integración: crear proyecto desde plantilla `api-rest` →
  `kb_projects` con las 3 KBs declaradas.
- Desbloquea el test humano `human_06_9_02` (que quedó pendiente).

**Queda fuera**:

- Editor de contenido de catálogo desde la UI (el catálogo se mantiene
  por repo + ingesta, no por panel).
- Versionado/diff del contenido del catálogo entre releases.
