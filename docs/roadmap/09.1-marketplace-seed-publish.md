## Resumen

El operador reporta dos cosas: el **marketplace aparece vacío** y **no se explica cómo añadir cosas**. La
verificación del código confirma: (1) NO hay seed de listings — `seed_playwright_listing` existe pero **no se
invoca** en `seeds/__main__.py`, así que el catálogo nace vacío; (2) publicar SÍ existe (`/admin/marketplace/
private`, task_09_16: pegar un manifest SKILL.md / tool YAML; `POST /marketplace/private/listings`,
`tenant_admin`) pero **no es descubrible** desde la pantalla principal ni hay guía del formato. Este plan
**siembra un catálogo oficial de arranque** (listings VERIFIED bajo la fuente `official-catalog`) y **hace
descubrible + documentado** el flujo de publicación.

## Alcance

**Entra**:

- **Seed del catálogo oficial** (idempotente): cablear `seed_playwright_listing` en el runner de seeds + añadir
  un loader que publica un conjunto curado de listings VERIFIED bajo `official-catalog` — la tool **Playwright**
  (ya tiene manifest+loader) + un puñado de **skills** empaquetadas como SKILL.md (a partir de las skills
  builtin / los docs de convenciones en `seeds/catalog/`: fastapi, nextjs, php-symfony, react, postgres…).
  Reutiliza el patrón de `marketplace/playwright.py` + `LocalArtifactFetcher` (raíz del official-catalog).
- **Descubrir publicar**: enlazar `/admin/marketplace/private` desde la pantalla principal del marketplace con
  un CTA claro ("Publicar"), y pulir la UX de publicación (área de manifest con **plantilla/ejemplo** SKILL.md y
  tool.yaml, ayuda de formato inline, feedback de validación 422 claro). RoleGuard `tenant_admin` (ya existe).
- **Guía** `docs/03-guides/publicar-en-marketplace.md`: formatos de manifest (SKILL.md, tool.yaml, mcp_server),
  niveles de confianza (verified/community/experimental), cómo publicar/despublicar, qué se deriva en servidor.
- Tests automáticos + changelog + fila en README.

**Queda fuera**:

- Cambiar el modelo del marketplace (sources/listings/installations/trust ya existen — Plan 09).
- Firma criptográfica de listings VERIFIED de terceros / fuentes remotas nuevas.
- Pago/monetización (no es alcance del producto).

## Decisiones clave

- **Listings oficiales = VERIFIED + `official-catalog` + global** (todos los tenants los ven, RLS de Fase A);
  se siembran a nivel plataforma. **Listings de tenant = COMMUNITY + privados** (publicados por `tenant_admin`
  vía la UI; aislados por RLS). No se mezclan.
- **Seed idempotente**: re-ejecutar el seed no duplica (upsert por identidad de listing, como `seed_playwright_listing`).
- **No reinventar publicar**: la UI + endpoints de publicación privada ya existen (task_09_16); este plan solo
  los hace **descubribles + documentados + más amables**, no los reescribe.
- **Contenido de skills reutilizado**: las skills builtin + los docs de `seeds/catalog/` son la materia prima de
  los listings SKILL oficiales (no se inventa contenido nuevo).
