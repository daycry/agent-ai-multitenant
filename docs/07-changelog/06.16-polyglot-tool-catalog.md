# Plan 06.16 — Catálogo de tools políglota (shell_exec asignable + runtime por stack)

## Resumen

El operador necesitaba que los agentes **lanzaran comandos del stack del
proyecto** (`php`, `composer`, `vendor/bin/phpunit`, `pest`, `npm`,
`dotnet`…), no sólo Python. La verificación confirmó que el motor **ya
era políglota** (runtime templates `php-phpunit` / `php-pest` /
`dotnet-test` / `node-*` en `shared_test_runtimes.catalog`, y un
`ShellExecTool` con allowlist por basename + timeout + argv `shlex` en
`agent_runtime/shell_exec.py`), pero **faltaba cablearlo y exponerlo**:
`shell_exec` no estaba en el catálogo `tools` ni se instanciaba con la
allowlist de un proyecto, el `Project` no tenía campos de allowlist ni de
stack, y los `run_*` tenían el runtime `python-pytest` fijo.

Este plan cierra el círculo: **config de proyecto** (allowlist
deny-by-default + runtime por defecto, migración **0072**), **`shell_exec`
asignable y cableado** por proyecto, **`run_*` resueltos por stack** (con
fallback backward-compatible) y una **UI amigable** (chips + presets por
stack) para configurarlo. Las dos decisiones de diseño están en el
**ADR 0045**.

> **Construido bajo override humano del operador.** El frontmatter del
> plan lo cierra el orquestador; esta entrada documenta lo implementado.

### Fase B — shell_exec asignable + cableado

- ✅ **`task_06_16_02`** — **`shell_exec` en el catálogo + instanciación
  por proyecto**. Añadido `shell-exec` → `shell_exec` al seed
  `builtin_tools.py` (`category='command'`, `implementation_type='builtin'`,
  `is_builtin=true`, `security_level='privileged'`, `input_schema
{command, cwd?}`). Cableado del runtime: `agent_runtime.__main__` lee
  `allowed_commands` del spec y registra un
  `ShellExecTool(allowed_commands=frozenset(...))` en el `ToolRegistry`.
  **Deny-all** si la lista está vacía; **clave ausente** ⇒ `shell_exec`
  no se registra (bare run / payload antiguo). El threading reutiliza la
  ruta de spec de 06.15 (ver más abajo).
  - **Tests**: `tests/integration/test_shell_exec_allowlist.py` (comando
    en allowlist se ejecuta; uno fuera → rechazado con la lista de
    permitidos; lista vacía → deny-all; el seed expone `shell_exec`
    asignable como básica privilegiada).

## Migraciones

**0072 — `projects.allowed_commands` + `default_runtime_template`**
(`20260601_0072_projects_command_config.py`). Aditiva y
**backward-compatible**: `allowed_commands TEXT[] NOT NULL DEFAULT '{}'`
(las filas existentes arrancan deny-all) + `default_runtime_template TEXT
NULL` (NULL = default por-tool, sin cambio para Python). Hereda la RLS por
tenant de `projects` (sin cambio de policy). **Reversible** (`downgrade`
dropea ambas columnas, restaura 0071 exacto), probada up/down/up. Head
único antes: `0071_model_prices_provider_id`; después:
`0072_projects_command_config`.

## Endpoints (sin endpoints nuevos)

No hay rutas nuevas: los dos campos viajan por el CRUD de proyecto
existente.

| Endpoint         | Método    | Rol mínimo     | Cambio                                                                |
| ---------------- | --------- | -------------- | --------------------------------------------------------------------- |
| `/projects`      | POST      | `tenant_admin` | acepta `allowed_commands` (default `[]`) + `default_runtime_template` |
| `/projects/{id}` | PATCH/PUT | `tenant_admin` | actualiza ambos; `allowed_commands: []` limpia a deny-all             |
| `/projects/{id}` | GET       | `tenant_user`  | devuelve ambos en `ProjectResponse`                                   |

## Threading de la config al runtime (reutiliza 06.15)

```
projects.{allowed_commands, default_runtime_template}
  → orchestrator.dispatch
  → ExecutionRequest.{allowed_commands, default_runtime_template}
  → workers.execution._agent_spec → AGENT_TASK_SPEC
  → agent_runtime.__main__
       · allowed_commands → ShellExecTool(...) en el ToolRegistry (`shell_exec`)
       · default_runtime_template → WiringContext.project_default_runtime → run_* (docker_command)
```

Sentinel de `allowed_commands` en el spec: clave **ausente** ⇒ no se
registra `shell_exec`; lista (incl. **`[]`**) ⇒ se registra; **`[]` =
deny-all**.

## Deny-by-default (NON-NEGOTIABLE)

- `shell_exec` ejecuta **sólo** binarios cuyo basename esté en
  `project.allowed_commands`. **Lista vacía ⇒ nada se ejecuta** (rechazo
  con la lista de permitidos en el error).
- Sigue siendo **argv** (`shlex`) + **timeout** + `cwd` confinado al
  `/workspace`. Nunca a través de una shell (sin inyección).
- `shell_exec` es **básica** (`is_builtin=true`) y **privilegiada**
  (`security_level=privileged`): la seguridad es un eje ortogonal a la
  taxonomía básica/avanzada (ADR 0044 / 0045).
