# Plan 09.1 — Marketplace: seed de catálogo oficial + publicar descubrible

## Resumen

El operador reportó dos cosas: el **marketplace aparecía vacío** y **no se
explicaba cómo añadir cosas**. La verificación del código lo confirmó: (1) NO
había seed de listings — `seed_playwright_listing` existía pero **no se
invocaba** en `seeds/__main__.py`, así que el catálogo nacía vacío; (2)
publicar SÍ existía (`/admin/marketplace/private`, `POST
/marketplace/private/listings`, `tenant_admin`) pero **no era descubrible** ni
estaba documentado. Este plan **siembra un catálogo oficial de arranque**
(listings `verified` bajo `official-catalog`, globales) y hace el flujo de
publicación **descubrible + documentado + más amable**. No reescribe el flujo
de publicación (ya existía del Plan 09): solo lo siembra, lo enlaza y lo
documenta.

> **Construido bajo override humano del operador.** El frontmatter del plan lo
> cierra el orquestador; esta entrada documenta lo implementado en las tareas
> 01-03.

## Contenido del seed oficial

El loader `seed_marketplace_listings` publica:

| Listing                      | Tipo  | Confianza  | Tenancy |
| ---------------------------- | ----- | ---------- | ------- |
| `playwright`                 | tool  | `verified` | global  |
| `python-fastapi-conventions` | skill | `verified` | global  |
| `react-nextjs-conventions`   | skill | `verified` | global  |
| `php-symfony-conventions`    | skill | `verified` | global  |
| `postgresql-best-practices`  | skill | `verified` | global  |
| `api-rest-guidelines`        | skill | `verified` | global  |

Las skills se derivan de los docs de convenciones que la plataforma ya envía
(no se inventa contenido nuevo). Cada SKILL.md pasa por el parser compartido y
se escribe a disco para que un tenant pueda instalarla, no solo navegarla.

## Migraciones

**Ninguna.** El plan se monta sobre las tablas del marketplace
(`marketplace_sources` / `marketplace_listings` / `marketplace_installations` /
`marketplace_audit_entries`) que **ya existían** desde el Plan 09. Un listing
oficial es una fila + un `manifest` JSONB; los SKILL.md son **datos** del seed
y el loader es el **código**. Head único antes y después del plan:
**`0071_model_prices_provider_id`**.

## Decisiones clave (recordatorio)

- **Oficiales = `verified` + `official-catalog` + globales** (los ve todo
  tenant vía la RLS de Fase A); se siembran a nivel plataforma.
- **De tenant = `community` + privados** (publicados por `tenant_admin` vía la
  UI; aislados por RLS). No se mezclan.
- **Seed idempotente**: re-ejecutar nunca duplica (upsert por identidad de
  listing, como `seed_playwright_listing`).
- **No reinventar publicar**: la UI + endpoints de publicación privada ya
  existían (Plan 09); este plan solo los hace descubribles + documentados + más
  amables.
