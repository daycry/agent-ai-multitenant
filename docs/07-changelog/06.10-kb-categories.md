# Plan 06.10 — Categorías de Knowledge Bases

## Resumen

Tras el Plan 06.9 las KBs pueden venir de tres fuentes (proyecto, agente,
built-in del platform). Con 20-30 KBs por tenant el listado plano de
`/admin/knowledge-bases` se vuelve inmanejable —el usuario lo señaló en los
tests humanos de 06.9—. Este plan añade un eje de **categoría** sobre las KBs:
categorías built-in del catálogo + categorías custom por tenant, con
agrupación en la UI y filtro en el listado.

## Cambios

### Backend — modelo, endpoints y seed

- **Migración** `kb_categories` + columna `knowledge_bases.category_id`
  (FK `ON DELETE SET NULL`, así borrar una categoría no rompe la KB) con RLS
  dual (aislamiento por `tenant_id` + lectura de built-ins del catálogo).
- ORM: clase `KbCategory` en `db/knowledge.py`; `KnowledgeBaseResponse`
  embebe el objeto `category`.
- **4 endpoints CRUD** de categorías con protección de built-ins (no se
  editan ni borran) y tests parametrizados.
- Filtro `?category=` en `GET /knowledge-bases` (acepta UUID o slug; se
  combina con el `?q=` existente).
- **Seed** `builtin_kb_categories.py`: 5 categorías default (`stack`, `role`,
  `compliance`, `architecture`, `process`); `BuiltinKB` gana `category_slug`
  y el seed categoriza las 6 KB canónicas.

### Frontend

- `/admin/knowledge-bases` agrupado por categoría en secciones colapsables;
  las KBs sin categoría caen al final.
- Selector de categoría en Crear/Editar KB, con opción inline
  "+ Nueva categoría".
- Nueva página `/admin/knowledge-bases/categories`: listado + CRUD para
  categorías custom; las built-in se muestran read-only.

### Documentación

- `docs/04-reference/rbac.md`: sección "Cómo usar las categorías" + los 4
  endpoints nuevos.

## Tests

- `tests/integration/test_kb_categories.py`: migración + RLS, CRUD,
  protección de built-ins, filtro `?category=`. Verde.

## Notas

- **Diferida** `task_06_10_09` (`<KbCombobox>` muestra `[<slug>] <name>` en
  el typeahead): el autocomplete ya muestra el modelo de embedding como dato
  secundario; añadir la categoría exige embeber `category` en cada item y no
  es crítico para la UX inicial. Sin impacto en el cierre del plan.
- Esta categorización aplicó `kb_categories` con `tenant_id NULL` para los
  built-ins; el Plan 06.12 la realineó al patrón canónico (A) del catálogo
  global (platform tenant + `is_builtin` + `_builtin_read`, ADR 0029).
