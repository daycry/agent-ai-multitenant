# Plan 06.6 — Admin UI gaps acumulados

## Resumen

Pase de pulido extenso sobre el admin-panel: tras cerrar Plan 06 quedaron
muchas piezas de UI a medio terminar (UUIDs tipeados a mano, modales
estrechas, descripciones sin markdown, falta de breadcrumbs, página de
escalado en estilo prototipo, sin admin general de Knowledge Bases…).
Este plan cubre todos esos gaps en una pasada, además de un par de
fixes de backend descubiertos durante los tests humanos (pgvector cast
roto en `/memories/{id}/similar`, OTel console exporter que mataba el
proceso bajo PowerShell).

## Cambios visibles

### Componentes compartidos nuevos

- [`components/layout/breadcrumb.tsx`](../../apps/admin-panel/components/layout/breadcrumb.tsx) —
  `<Breadcrumb>` genérico + `<ProjectBreadcrumb>` que fetchea el
  proyecto por id. Visual: pill con borde, icono `Home` en "Proyectos",
  chevron entre items.
- [`components/ui/entity-combobox.tsx`](../../apps/admin-panel/components/ui/entity-combobox.tsx) —
  typeahead server-side genérico. Cualquier endpoint con `?q=&limit=`
  lo consume. Debounce 250ms, cache 30s por TanStack Query.
- [`components/ui/project-combobox.tsx`](../../apps/admin-panel/components/ui/project-combobox.tsx)
  y [`team-combobox.tsx`](../../apps/admin-panel/components/ui/team-combobox.tsx) —
  wrappers especializados. Sustituyen los "pega aquí el UUID" del
  admin.
- [`components/ui/markdown-textarea.tsx`](../../apps/admin-panel/components/ui/markdown-textarea.tsx) —
  tabs Editar / Vista previa, renderiza vía `plan-draft-md.tsx`
  (extendido en este plan con italics / inline code / links /
  strikethrough; sin nueva dependencia externa).
- [`components/ui/view-toggle.tsx`](../../apps/admin-panel/components/ui/view-toggle.tsx) —
  Lista / Kanban.
- [`components/ui/dialog.tsx`](../../apps/admin-panel/components/ui/dialog.tsx) —
  añadido prop `size`, default `lg` (`max-w-2xl`), padding `px-6 py-5`.

- `/admin/projects/[id]/mcp-servers` — **picker categorizado de las 22

  Create / edit / delete (confirm-by-name) / grant a proyecto vía
  `<ProjectCombobox>`. Hasta ahora los endpoints backend existían sin

- `/admin/executions/[id]` — `STATUS_VARIANT` reordenado por workflow.
- Sidebar (`admin-shell.tsx`) — añadido item "Knowledge Bases" entre

### Backend (extensiones + fixes)

- `GET /mcp-catalog` — expone las 22 plantillas verificadas que viven
  en `shared_mcp.catalog.CATALOG` como JSON. El picker del MCP dialog
  las consume.
- `GET /projects?q=<text>&limit=<int>` — filtro substring case-
  insensitive sobre el nombre + paginación para typeahead. Lo usa el
  `<ProjectCombobox>`.
- `GET /teams?q=<text>&limit=<int>` — idem para teams.
- **Fix `/memories/{id}/similar`** — el código pasaba
  `str(src.embedding)` como bind param, y `str(numpy_array)` produce
  `[0.1 0.2 0.3]` (espacios), que pgvector rechaza en
  `CAST(... AS vector)`. Misma receta que `memorizer/recall.py` y
  `rag/search.py`: `","join(f"{x:.6f}" ...)`.
- **OTel console exporter opt-in** — el `ConsoleSpanExporter` escribe
  JSON a stdout en cada request, lo que en Windows + PowerShell rompe
  el wrapping del proceso (cada línea se trata como
  `NativeCommandError` y termina matando uvicorn). Ahora opt-in vía
  `API_SERVER_OTEL_CONSOLE=1`.

### CI fixes (descubiertos durante la verificación)

- **`docker/agent-runtimes/python-pytest/Dockerfile`** — quitada la
  dependencia `pytest-junitxml>=1.0` que ya no existe en PyPI (pytest
  tiene `--junitxml` built-in).
- **`docker/agent-runtimes/go-test/Dockerfile`** — pin de gotestsum a
  `v1.12.1` (la `@latest` resuelve a v1.13.0 que requiere Go 1.24+,
  incompatible con `golang:1.22-bookworm`).
- **`docker/agent-runtimes/rust-cargo/Dockerfile`** — pin de
  cargo-nextest a `v0.9.85` (la `@latest` requiere rustc 1.91+,
  incompatible con `rust:1.79-slim`).
- **`pyproject.toml`** — añadido `pythonpath = ["."]` al pytest
  config. Sin esto, `pytest ...` (el bin) ejecutado desde CI no
  añade CWD a `sys.path` en Python 3.11+ → 14 tests del Plan 06
  fallaban con `ModuleNotFoundError: No module named 'tests'`.

## Decisiones técnicas notables

### Stack ≠ Rol (Plan 06.9 emergió de aquí)

Durante los tests humanos surgió la pregunta: si añadimos KBs a
nivel de agente para que `backend_dev` "sepa diseñar APIs", ¿necesitamos
`backend_dev_python`, `backend_dev_php`, `backend_dev_js`, …? La
respuesta es no — el rol del agente es agnóstico de stack. El
conocimiento de stack vive con el proyecto (KB de stack pre-granted
desde la plantilla del proyecto); el conocimiento de rol con el agente
template. Esta decisión se materializa en el nuevo
[Plan 06.9 — Agent-scoped KBs](../roadmap/06.9-agent-scoped-kbs.md).

### Modales más holgadas por defecto (`size="lg"`)

El `<Dialog>` original tenía `max-w-md` (448 px) hardcodeado. Para
descripciones markdown y formularios con varios campos, eso quedaba
encajonado. El nuevo default es `max-w-2xl` (672 px); el prop `size`
acepta `sm` / `md` / `lg` / `xl` / `2xl` para casos extremos. Los
diálogos pequeños (confirm-delete) siguen funcionando — solo gana
breathing room.

### Tasks planless visibles (sub-section nueva)

El data model permite `tasks.plan_id = NULL` (tarea project-scoped sin
plan). Antes esas tareas existían en la BD pero no aparecían en
ninguna pantalla. La nueva sub-section `/admin/projects/[id]/tasks`
las lista y permite filtrar por "Sin plan" / "Plan X" / "Plan Y" —
respetando la doctrina CLAUDE.md §6 (no mezclar tareas de varios
planes en una columna).

### Vault path oculto al project owner (principio de menor conocimiento)

El path `vault:secret/data/mcp/jira/{project_uuid}` no aparece en la UI
del project owner — solo una info card "🔒 Esta integración necesita
credenciales. Avisa al admin del tenant." El path técnico está
detrás de un expander "Detalles técnicos" para devops. El project
owner no aprende ni la ruta Vault ni el UUID del proyecto.
