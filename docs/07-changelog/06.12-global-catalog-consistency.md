# Plan 06.12 — Consistencia del catálogo global

## Resumen

Implementa [ADR 0029](../05-architecture-decisions/0029-platform-tenant-y-catalogo-global.md):
unifica el mecanismo del **catálogo global** en el patrón canónico (A) —
_platform tenant + bandera `is_builtin` + política `_builtin_read`_ — que
ya usaban `agents`/`skills`/`tools`/`teams`/`approval_policy_templates`.

Resuelve dos cosas que la auditoría del Plan 06.11 destapó:

1. **Las KB built-in eran invisibles.** Estaban sembradas bajo el
   platform tenant pero a `knowledge_bases` se le olvidó su política de
   catálogo en el Plan 04. Ahora son visibles y grantables.
2. **`kb_categories` era el outlier.** El Plan 06.10 la hizo con
   `tenant_id NULL`; ahora se alinea al patrón (A).

## Cambios

### Backend — `knowledge_bases`

- **Migración 0029**: `is_builtin BOOLEAN NOT NULL DEFAULT false` +
  índice parcial + política `knowledge_bases_builtin_read FOR SELECT
USING (is_builtin = true)` + backfill (filas del platform tenant →
  `is_builtin=true`). `tenant_id` permanece `NOT NULL`.
- ORM/schema/seed: `is_builtin` en `KnowledgeBase`,
  `KnowledgeBaseResponse` y `to_kb_response`; el seed marca las 6 KB
  canónicas `is_builtin=true`.
- **Resolver de visibilidad** (`resolve_visible_kbs` +
  `visibility_filter_clause`): admiten una KB built-in **cuando está
  granteada** al proyecto/agente. Built-in **no** es auto-visible en
  RAG. Built-in chunks viven bajo el platform tenant; el tenant-guard
  del filtro los deja pasar solo si su KB es built-in y está granteada,
  manteniendo el aislamiento cross-tenant.

### Backend — `kb_categories`

- **Migración 0030**: `is_builtin` + índice parcial + backfill
  (`tenant_id NULL` → `PLATFORM_TENANT_ID`, `is_builtin=true`) + swap de
  `kb_categories_builtin_read` de `USING (tenant_id IS NULL)` a
  `USING (is_builtin = true)`. Downgrade reversible.
- ORM: `is_builtin` pasa de propiedad derivada a columna real.
- Seed + endpoints (`_ensure_writable`, check de 409, ordenación) usan
  la columna.

### Frontend

- `/admin/knowledge-bases`: las KB built-in muestran un badge **Built-in**
  y ocultan editar/borrar (conservan Grant + Asignaciones).

## Tests

- `tests/integration/test_builtin_kb_visibility.py` (5): built-in
  granteado visible + recuperable; no-granteado fuera del RAG;
  aislamiento cross-tenant en resolver y en el filtro de chunks.
- `test_kb_categories.py` actualizado al patrón (A).

## Notas

- Este plan resuelve la **alcanzabilidad** del catálogo built-in, no su
  **población**: las KB built-in siguen sin chunks hasta que un proceso
  de ingesta de catálogo (futuro) las llene.
- Destraba el cableado de `apply_template_kb_grants` (queda para el plan
  del wizard de proyectos).
