# Plan 06.13 — Contenido del catálogo + auto-grant por plantilla

## Resumen

Los Planes 06.11/06.12 dejaron el subsistema KB **funcional y consistente**
(la ingesta corre, el RAG está saneado, las KB built-in son
visibles/grantables vía patrón A, ADR 0029), pero con dos piezas de
seguimiento pendientes: las KB built-in estaban **vacías** (contenedores sin
chunks) y `apply_template_kb_grants` era **código muerto**. Este plan cierra
ambas: pobla el catálogo built-in con contenido curado e indexado, y cablea
el auto-grant de KBs al crear un proyecto desde plantilla.

## Cambios

### Contenido del catálogo

- **Corpus `.md` curado** (`task_06_13_01`): ficheros markdown versionados en
  el repo, uno por cada una de las 6 KB built-in. El catálogo se mantiene por
  repo + ingesta, no por panel de UI.
- **Proceso de ingesta de catálogo** (`task_06_13_02`): script/seed
  **idempotente** que indexa el corpus como `documents` + `chunks` bajo
  `PLATFORM_TENANT_ID`. Reejecutarlo no duplica filas.

### Auto-grant por plantilla

- **Cableado de `apply_template_kb_grants`** (`task_06_13_03`): se invoca tras
  crear un proyecto desde plantilla, de modo que las KBs de la plantilla
  quedan pre-concedidas al nuevo proyecto. Deja de ser código muerto.

## Tests

- `tests/integration/test_catalog_ingestion.py`: indexación del corpus bajo
  el platform tenant + idempotencia del seed. Verde.
- Test del auto-grant tras crear proyecto desde plantilla.

## Notas

- **Queda fuera** (por decisión de alcance): editor de contenido de catálogo
  desde la UI y versionado/diff del contenido entre releases.
- Con este plan una KB built-in concedida **sí aporta contenido al RAG**
  (antes era un contenedor navegable sin chunks).
